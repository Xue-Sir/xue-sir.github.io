在一块宽屏显示器上同时使用浏览器、编辑器、终端和资料窗口时，固定的工作区边界可以减少窗口反复调整。DesktopSplit 面向这类场景，将一台显示器的工作区划分为多个矩形区域，并让每个区域拥有独立的最大化范围。

工具运行在现有显示器工作区上，不创建虚拟显示器，也不安装显示驱动。普通窗口保持原位置；窗口最大化时，工具根据窗口中心点所在的区域调整大小。

## 摘要

**适用人群：** 在一块宽屏显示器上同时处理浏览器、编辑器、终端和资料，希望获得稳定分区，又不想安装虚拟显示器驱动或改变普通窗口移动习惯的 Windows 用户。

**核心机制：** 把显示器工作区看成多个矩形区域。窗口中心点决定区域归属，用户执行原生最大化后，工具把窗口填充到对应区域。普通窗口不会被自动移动或吸附。

DesktopSplit 以托盘程序形式运行，可随 Windows 启动，布局设置保存在本地，并提供目录版和单文件版两种自包含 EXE 发布方式。

## 1. 窗口位置决定区域归属

DesktopSplit 不把窗口拖到屏幕边缘作为触发条件，窗口移动和区域最大化相互独立：

- 普通窗口保持当前位置和大小；
- 窗口中心点落在哪个区域，就归属于哪个区域；
- 点击最大化按钮或双击标题栏后，窗口填充中心点所在区域；
- 窗口还原时，回到工具接管前的正常位置；
- 暂停分区后，恢复 Windows 默认的最大化行为。

工具不执行自动吸附，窗口拖动过程保持 Windows 默认行为。窗口可以先放到合适的位置，再决定是否最大化，适合需要频繁调整窗口位置、又希望最大化尺寸固定的工作流。

## 2. 一个 4/5 + 1/5 的例子

常见布局是把屏幕分成左右两块：左侧约占 4/5，右侧约占 1/5。

假设当前显示器工作区为 `2048 × 1112` 像素，布局可以表示为：

```text
┌──────────────────────────────────────────────┬──────────┐
│                                              │          │
│              主工作区 1638 × 1112            │ 侧边区   │
│                                              │ 410×1112 │
└──────────────────────────────────────────────┴──────────┘
```

浏览器放在左侧并最大化时，只会填充左侧区域；终端、音乐播放器或参考资料放在右侧并最大化时，只会填充右侧区域。这里的“屏幕”指窗口管理行为中的区域，Windows 设置中不会出现一台新增的显示器。

## 3. 设置页同时显示比例和像素

仅显示 `80% / 20%` 时，比例容易理解，但无法直接说明窗口最终占用多少空间。不同显示器、任务栏位置和显示缩放会影响工作区尺寸，因此设置页同时展示比例和实际像素。

设置页会显示：

- 当前设置窗口所在显示器的工作区宽高；
- 工作区是否已经扣除任务栏；
- 预览中每个区域的实际宽度和高度；
- 每个区域可以直接输入的像素宽度。

对于左右分区，所有区域共用工作区高度，用户只需输入各列宽度。例如输入 `1638` 和 `410`，工具会检查两者合计是否等于工作区宽度 `2048`。合计正确后，布局转换为比例保存，换到分辨率不同的显示器时仍可按相同比例工作。

分割线也可以直接在预览中拖动。拖动和像素输入使用同一份布局数据，比例标签、像素尺寸和预览会同步更新。

## 4. 实现方式

项目使用 C# WPF 负责设置窗口和应用生命周期，使用 Win32 API 处理窗口枚举、显示器工作区、窗口状态和窗口位置。

### 4.1 布局保存为归一化矩形

布局以 `0..1` 范围内的归一化矩形保存，不固定写入某一台显示器的绝对像素：

```text
区域左边界 = 0.0
区域宽度   = 0.8
区域顶部   = 0.0
区域高度   = 1.0
```

窗口需要填充区域时，程序读取窗口所在显示器的工作区，将归一化坐标换算为 Win32 像素矩形。这样既能支持 4/5 布局，也能适应不同分辨率和任务栏工作区。

### 4.2 用轻量轮询识别最大化

首版通过较短间隔枚举顶层窗口，识别用户刚刚执行的原生最大化动作。运行过程中无需安装驱动，也无需引入复杂的窗口钩子。

识别到最大化后，工具会：

1. 读取窗口最大化前的正常位置；
2. 找到窗口中心点所在的显示器和区域；
3. 恢复窗口，再把它调整到区域矩形；
4. 记录接管状态，下一次还原时恢复原始位置。

如果用户手动移动或调整被管理窗口，窗口会退出自定义最大化状态，工具不继续强制控制。

## 5. 托盘、开机启动和配置

DesktopSplit 是托盘优先的工具。启动后不主动弹出设置窗口，用户可以从系统托盘图标打开设置、暂停分区或退出程序。

开机启动使用当前用户的 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 项，不需要管理员权限。布局、预设和开机启动开关保存在当前用户的应用数据目录中。

应用图标和托盘图标使用同一套多尺寸 ICO 资源，包含 16 到 256 像素尺寸，适配任务栏、资源管理器和系统托盘中的不同显示尺寸。

DesktopSplit 提供 Windows x64 自包含发布包。目标电脑不需要预先安装 .NET 运行时，两个运行包都带有应用图标和托盘图标。

| 发布包 | 压缩包大小 | 适用场景 |

| 单文件版 `DesktopSplit-single-win-x64-20260922.zip` | 75,638,442 字节，约 72.13 MiB | 解压后直接运行一个 `DesktopSplit.exe`，适合日常使用和临时复制 |
| 目录版 `DesktopSplit-directory-win-x64-20260922.zip` | 79,985,297 字节，约 76.28 MiB | 运行文件和 .NET 运行时放在同一目录，适合作为固定目录或安装器输入 |

单文件版的压缩包更小，文件数量也更少，适合只关心运行程序的用户。目录版解压后约占 194.46 MiB，包含 474 个文件，适合需要保留运行时目录结构的场景。

当前版本暂未加入 MSI 或 Inno Setup 安装器，目录版可以直接放入指定安装目录。

## 7. 适用范围和限制

公开版本的功能边界如下：

- 面向 Windows 10 x64；
- 使用现有显示器工作区，不创建真正的虚拟显示器；
- 不提供自动吸附，窗口移动保持系统默认行为；
- 暂不处理全屏程序、UAC 安全桌面和部分特殊置顶窗口；
- 多显示器使用同一套归一化布局，暂不提供每台显示器独立配置；
- 状态检测采用轻量轮询，复杂窗口程序需要在真实桌面环境中验证。

如果需求是让系统识别出多台独立显示器，或需要拖动窗口时自动吸附，DesktopSplit 的工作方式不匹配。它更适合把一块宽屏显示器划出稳定的主工作区和侧边区域，并保持窗口移动习惯不变。
