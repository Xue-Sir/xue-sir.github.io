我经常需要在一块宽屏显示器上同时使用主工作区和侧边信息区。浏览器、编辑器、终端和文档窗口各自占据一部分屏幕时，真正需要的并不一定是第二块物理显示器，而是“像有多个屏幕一样”的最大化行为。

DesktopSplit 就是为这个场景做的一个 Windows 桌面工具。它不创建虚拟显示器，也不安装显示驱动，而是把当前显示器的工作区划分成多个矩形区域。窗口在哪里，就属于哪个区域；用户执行最大化时，窗口才会填充它所在的区域。

<!--more-->

## 摘要

**Who is this for?** Windows users who work on one wide monitor and want several stable workspace regions without installing a virtual display driver or changing the normal movement behavior of windows.

**Core idea:** Treat a monitor work area as a set of rectangles. The center point of a window determines its region, and a native maximize action is converted into a region-sized maximize. Normal windows are not automatically moved or snapped.

DesktopSplit is intentionally small. It runs in the tray, starts with Windows when enabled, stores layout settings locally, and provides both a directory self-contained build and a single-file self-contained EXE.

---

**这是写给谁的？** 在一块宽屏显示器上同时处理浏览器、编辑器、终端和资料，希望获得稳定分区，但不想安装虚拟显示器驱动或改变普通窗口移动习惯的 Windows 用户。

**核心观点：** 把显示器工作区看成多个矩形区域。窗口中心点决定它属于哪个区域，用户执行原生最大化后，工具把窗口填充到该区域；普通窗口不会被自动移动或吸附。

## 1. 我想要的不是自动吸附

很多窗口管理工具把重点放在“拖到边缘就吸附”。这种行为适合一部分工作流，但不是我想要的行为：窗口可能只是暂时被拖到某个位置，并不代表我要立即改变它的大小。

DesktopSplit 的规则很简单：

- 普通窗口保持当前位置和大小；
- 窗口中心点落在哪个区域，就把它认为属于哪个区域；
- 点击最大化按钮或双击标题栏后，才填充中心点所在区域；
- 窗口还原时，回到工具接管前的正常位置；
- 暂停分区后，恢复 Windows 默认的最大化行为。

这套规则把“窗口移动”和“窗口最大化”分开了。用户可以先把窗口放好，再决定是否最大化，不需要和自动吸附行为竞争。

## 2. 一个 4/5 + 1/5 的例子

最常用的布局是把屏幕分成左右两块：左边约占 4/5，右边约占 1/5。

假设当前显示器工作区是 `2048 × 1112` 像素，那么布局可以近似为：

```text
┌──────────────────────────────────────────────┬──────────┐
│                                              │          │
│              主工作区 1638 × 1112            │ 侧边区   │
│                                              │410×1112  │
└──────────────────────────────────────────────┴──────────┘
```

浏览器放在左侧并最大化时，只会填充左侧区域；终端、音乐播放器或参考资料放在右侧并最大化时，只会填充右侧区域。这里的“屏幕”是行为上的区域，不是 Windows 设置中真正新增的显示器。

## 3. 设置页同时显示比例和像素

早期只显示 `80% / 20%` 时，比例虽然容易理解，但不够精确。不同显示器、任务栏位置和显示缩放会让最终尺寸产生差异，所以当前设置页增加了实际像素信息。

设置页会显示：

- 当前设置窗口所在显示器的工作区宽高；
- 工作区是否已经扣除任务栏；
- 预览中每个区域的实际宽度和高度；
- 每个区域可以直接输入的像素宽度。

对于当前的垂直分区，所有区域共用工作区高度，用户只需要输入各列宽度。例如输入 `1638` 和 `410`，工具会检查两者合计是否等于当前工作区宽度 `2048`。合计正确后，布局会转换为比例保存，因此换到另一台分辨率不同的显示器时仍然可以按相同比例工作。

除了手动输入，也可以拖动预览中的分割线。拖动和像素输入使用同一份布局数据，比例标签、像素尺寸和预览会同步更新。

## 4. 实现方式

项目使用 C# WPF 负责设置窗口和应用生命周期，使用 Win32 API 处理窗口枚举、显示器工作区、窗口状态和窗口位置。

### 4.1 布局保存为归一化矩形

布局不会把某一台显示器的绝对像素写死，而是保存为 `0..1` 范围内的归一化矩形：

```text
区域左边界 = 0.0
区域宽度   = 0.8
区域顶部   = 0.0
区域高度   = 1.0
```

窗口真正需要填充时，再读取它所在显示器的工作区，把归一化坐标换算为 Win32 像素矩形。这样既能支持 4/5 布局，也能适应不同分辨率和任务栏工作区。

### 4.2 用轻量轮询识别最大化

首版没有安装驱动，也没有引入复杂的窗口钩子，而是以较短间隔枚举顶层窗口，识别用户刚刚执行的原生最大化动作。

识别到最大化后，工具会：

1. 读取窗口最大化前的正常位置；
2. 找到窗口中心点所在的显示器和区域；
3. 恢复窗口，再把它调整到区域矩形；
4. 记录这次接管状态，下一次还原时恢复原始位置。

如果用户手动移动或调整了被管理窗口，它会退出自定义最大化状态，不继续强行控制。

## 5. 托盘、开机启动和配置

DesktopSplit 是托盘优先的工具。启动后不主动弹出设置窗口，用户可以从系统托盘图标打开设置、暂停分区或退出程序。

开机启动使用当前用户的 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 项，不需要管理员权限。布局、预设和开机启动开关保存在当前用户的应用数据目录中。

应用图标和托盘图标使用同一套多尺寸 ICO 资源，包含 16 到 256 像素尺寸。这样在任务栏、资源管理器和系统托盘中的缩放都能保持清晰。

## 6. 两种 Windows 发布包

当前准备了两种 Windows x64 自包含发布方式：

- **目录版**：`DesktopSplit.exe` 和 .NET 运行时文件放在同一个目录，适合放入固定安装目录或交给安装器；
- **单文件版**：程序、运行时和原生依赖合并为一个 `DesktopSplit.exe`，适合直接复制运行。

两种版本都不要求目标电脑预先安装 .NET 运行时，也都带有应用图标和托盘图标。当前还没有加入 MSI 或 Inno Setup 安装器，目录版可以作为后续安装器的输入目录。

## 7. 当前边界

这是一个面向个人工作流的首版，仍有一些明确边界：

- 暂不创建真正的虚拟显示器；
- 暂不实现自动吸附；
- 暂不处理全屏程序、UAC 安全桌面和特殊置顶窗口；
- 多显示器目前使用同一套归一化布局，不提供每台显示器独立配置；
- 状态检测采用轻量轮询，复杂窗口程序仍需要在真实桌面上验证；
- 当前项目还在整理首次 GitHub 项目仓库和发布附件。

下一步会继续验证不同 DPI 缩放、任务栏位置、多显示器切换以及浏览器等真实窗口的最大化和还原行为，再决定是否加入更多布局编辑能力和正式安装器。
